# Sentient 2.0 — Plan 2: Native Brain Spine (Runtime, ReAct Loop, Tools, Cancellation)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the gateway run its own agent loop. A `SessionRuntime` per authenticated session drives a native ReAct loop against an OpenAI-compatible provider, calls MCP tools (foreground) and delegates to a native Hermes process (background) through a fail-closed permission gate, and streams text back over the existing WebSocket — walking end-to-end, text-only, against the `try-chat.ts` dev harness.

**Architecture:** The Plan 1 foundation (principal → `AccessManager` → `Capability` → `SessionStore` → `projectForModel`) is threaded into a runtime. `SessionRuntime` owns one turn at a time, re-reading the store's model projection at the top of every ReAct iteration (so a mid-flight stimulus *steers* the running turn). The provider, tool broker, MCP client, and Hermes delegate all sit behind interfaces so they mock in unit tests and hit real services only under `@live`. Cancellation (barge-in / interrupt) hits the turn's `AbortController` from outside the loop.

**Tech Stack:** Bun + TypeScript (strict), the `openai` npm package (OpenAI-compatible chat streaming), the `@modelcontextprotocol/sdk` client (streamable-HTTP MCP transport), `Bun.spawn` (Hermes one-shot), zod, `bun test` (unit) + Vitest (`@live` integration).

**Spec:** `docs/superpowers/specs/2026-07-23-sentient-2.0-native-orchestrator-design.md` — this plan implements build-order slices 3, 4, 5 and the composition-root blockers Plan 1 recorded. Voice/TTS (§6), the full client-facing wire contract + renames (§7), client UI (§7.1), and compaction (§8) are **Plan 3/4** and explicitly out of scope here.

**Predecessor:** Plan 1 (`docs/superpowers/plans/2026-07-23-sentient-2.0-plan1-foundation.md`) is merged/on-branch. Its progress ledger (`.superpowers/sdd/progress.md`) records the blockers this plan clears and the constraints this plan must honor.

## Global Constraints

- **Design-first.** Build to the 2.0 spec. Existing code is a wiring target; never resurrect a deleted construct.
- **No ambient authority.** Identity flows as an explicit `UserPrincipal`; authority as an explicit `Capability`. No module-level "current user". A `SessionRuntime` for user A must be unreachable from user B (the isolation contract test guards this).
- **One turn per `SessionRuntime` at a time.** A stimulus never spawns a second concurrent loop. It steers the running turn (append to store; the loop re-reads the projection next iteration) or fires the next turn at turn end.
- **Immutable tool set.** `tools[]` sent to the provider is fixed per session — never mutated per turn. Permission is enforced at the call (L3 PDP), never by hiding a tool. This is both a caching property and a security property.
- **Append-only history.** All conversation state is written through `SessionStore.append`. Never mutate a committed entry.
- **Late/out-of-band tool results.** A background-task completion arriving after its block MUST be appended as a `system` or `trigger` entry, NEVER as a second `tool_result` for an already-answered `tool_call` id (the model projection pairs by block adjacency; a late `tool_result` would be dropped and the model would re-issue the call). This is recorded in `model-projection.ts`'s header.
- **Every provider/tool/subprocess call takes an `AbortSignal`** and respects it (stop consuming, stop yielding, release, do not throw) — per `.claude/rules/decorator-pattern.md` and `.claude/rules/provider-integration.md`.
- **Timeout every external call.** Provider, MCP tool, Hermes delegate — each bounded by a config timeout matched to its worst-case latency.
- **Tagged logger everywhere** (`getLog`), hierarchical tags, no bare `console.*`. Log every boundary/classifier/fallback decision with a `reason`. Log ids (userId, sessionId, turnId, toolCallId) and counts/elapsed on data ops. Log `cached_tokens`/`cacheHitRatio` on every provider stream-end (a ~6-line prior-art lesson — every caching pitfall is invisible without it).
- **Every tunable in `gateway/config.yaml`** with an inline comment. No magic numbers in source.
- **Cohesion drives decomposition.** No line-count rule.
- **Test bar** (`.claude/rules/testing.md`): pin a wire/protocol contract, an FSM/invariant with a documented learning, a security boundary, or an `@live` flow. Do not test DI wiring, factories, types, or constants.
- **Commands:** `source scripts/env.sh` first. Unit: `cd gateway && bun test src/<path>`. Integration/@live: `cd gateway && bun run test:int`. Typecheck: `cd gateway && bun run typecheck`. Lint: `bun run lint` (root). Full: `bun run test` (root, vitest).

## Prior-art constraints (mined from the pre-Hermes archive — do not relearn these)

- **Flush accumulated tool-call deltas at stream end regardless of `finish_reason`.** A provider finishing `stop`/`length` mid-tool-call must still yield the accumulated calls, or the transcript silently diverges from what ran.
- **Key streaming tool-call slots by `index`, not `id`.** Providers may send `index`+`name` before `id`; keying on a not-yet-arrived id double-dispatches.
- **Enforce per-turn policy (dedupe, budget, PDP) at ONE shared choke point** across every dispatch path. Two paths = one gets forgotten.
- **Never make a user-facing output channel a tool.** Text streams from the assistant deltas; it is never a `speak` tool call (that forced 2 round-trips/turn historically).
- **Self-output must not wake the loop.** Appending an assistant/tool entry must not itself trigger a new turn.

```typescript
// Accumulates streaming OpenAI tool_call deltas. Keyed by INDEX (the only
// field guaranteed on every delta); id/name/arguments are late-bound as they
// arrive. flush() drains and resets. Prior art: keying on id double-dispatches
// when a provider sends index+name before id.
import type { ChatToolCall } from "../store/model-projection.js";

interface ToolCallDelta {
  index: number;
  id?: string;
  function?: { name?: string; arguments?: string };
}

export class ToolCallAccumulator {
  private readonly pending = new Map<number, { id: string; name: string; arguments: string }>();

  feed(deltas: ToolCallDelta[]): void {
    for (const d of deltas) {
      const cur = this.pending.get(d.index) ?? { id: "", name: "", arguments: "" };
      if (d.id) cur.id = d.id;
      if (d.function?.name) cur.name += d.function.name;
      if (d.function?.arguments) cur.arguments += d.function.arguments;
      this.pending.set(d.index, cur);
    }
  }

  flush(): ChatToolCall[] {
    const out: ChatToolCall[] = [];
    for (const [, c] of this.pending) {
      if (!c.id || !c.name) continue; // never emit a half-formed call
      out.push({ id: c.id, type: "function", function: { name: c.name, arguments: c.arguments || "{}" } });
    }
    this.pending.clear();
    return out;
  }
}
```

```typescript
import OpenAI from "openai";
import { getLog } from "../logging/logger.js";
import type { OrchestratorConfig } from "@sentient/config";
import type { ProviderClient, ProviderRequest, ProviderStreamChunk } from "./provider-client.js";
import { ToolCallAccumulator } from "./tool-call-accumulator.js";

const log = getLog(["sentient", "provider", "openai"]);

export function createOpenAIProvider(
  cfg: OrchestratorConfig["provider"],
  apiKey: string,
): ProviderClient {
  const client = new OpenAI({
    apiKey,
    baseURL: cfg.base_url,
    defaultHeaders: { "HTTP-Referer": cfg.site_name, "X-Title": cfg.site_name },
    timeout: cfg.request_timeout_ms,
  });

  return {
    async *stream(req: ProviderRequest): AsyncGenerator<ProviderStreamChunk> {
      const startedAt = Date.now();
      const hasTools = req.tools.length > 0;
      log.info("stream-start", { model: cfg.model, messageCount: req.messages.length, toolCount: req.tools.length });

      const response = await client.chat.completions.create(
        {
          model: cfg.model,
          messages: req.messages as OpenAI.Chat.ChatCompletionMessageParam[],
          stream: true,
          stream_options: { include_usage: true },
          max_tokens: cfg.max_output_tokens,
          ...(hasTools && { tools: req.tools as OpenAI.Chat.ChatCompletionTool[], tool_choice: "auto" }),
        },
        { signal: req.signal },
      );

      const acc = new ToolCallAccumulator();
      let finishReason = "stop";
      let usage: ProviderStreamChunk extends { usage?: infer U } ? U : never = undefined as never;

      for await (const chunk of response) {
        if (req.signal.aborted) return; // stop consuming, do not throw
        const choice = chunk.choices[0];
        if (choice?.delta?.content) yield { type: "text", content: choice.delta.content };
        if (choice?.delta?.tool_calls) acc.feed(choice.delta.tool_calls as never);
        if (choice?.finish_reason) finishReason = choice.finish_reason;
        if (chunk.usage) {
          usage = {
            promptTokens: chunk.usage.prompt_tokens ?? 0,
            cachedTokens: chunk.usage.prompt_tokens_details?.cached_tokens ?? 0,
            completionTokens: chunk.usage.completion_tokens ?? 0,
          } as never;
        }
      }

      // Flush accumulated tool calls REGARDLESS of finish_reason — a provider
      // finishing "stop"/"length" mid-call must not silently drop them.
      for (const tc of acc.flush()) yield { type: "tool_call", toolCall: tc };

      const cacheHitRatio = usage && usage.promptTokens > 0 ? usage.cachedTokens / usage.promptTokens : 0;
      log.info("stream-end", { durationMs: Date.now() - startedAt, finishReason, ...(usage ?? {}), cacheHitRatio: Number(cacheHitRatio.toFixed(3)) });
      yield { type: "done", finishReason, usage };
    },
  };
}
```
(Adjust the `usage` typing to satisfy strict TS cleanly — the shape is `{promptTokens, cachedTokens, completionTokens} | undefined`; a local `let usage: NonNullable<...> | undefined` is fine.)
