# Phase 5.5 — Opus End-to-End Pivot Handover

**Date:** 2026-05-14
**Branch:** feature/esp32-cube-v2-rescope (merged into develop)
**Plan:** docs/superpowers/plans/2026-05-13-phase5.5-opus-end-to-end-pivot.md

## TL;DR

Gateway is now a true codec-agnostic byte pipe for audio. Webui mic + TTS playback both run opus end-to-end. STT server natively accepts opus (per-conn URL query negotiation). PCM silence-carrier hack and server-side energy gate both deleted. Client-edge RNNoise neural noise gate replaces dumb RMS gate. Cube C-series tasks (C1–C8) deferred to **Phase 6 cube-sdk** — see "What's deferred" below.

## What's done

### Workstream A — Webui TTS playback (opus IN)

- `gateway/webui/src/audio/opus-decoder.ts` — WebWorker-backed `ogg-opus-decoder`. Lazy WASM chunk (separate Vite chunk, ~200 KB gz). Closed/ready/pending lifecycle state machine with use-after-free guard. Local `.d.ts` override for upstream's mistyped sync `decode()`.
- `gateway/webui/src/hooks/use-voice-client.ts` — per-cycle `opusDecoder.reset()` on `onAudioStart` + `onPlaybackStop`; close on unmount.
- `gateway/src/providers/tts/fish-audio-protocol.ts` — named constants for opus/mp3 bitrate allowed-sets + fallbacks; replaces magic numbers.
- `gateway/src/providers/tts/fish-audio-provider.ts` — demoted `fish-event-dropped` log INFO→DEBUG.
- `gateway/config.yaml` — opus format/bitrate/sample_rate doc comments updated; "produces static" lore removed.

### Workstream B — STT service opus uplink (per-conn URL negotiation)

- `capabilityServices/STTService/pyproject.toml` + `requirements.txt` + `Dockerfile` — `opuslib>=3.0.1` + `libopus0` apt.
- `capabilityServices/STTService/src/stt_service/opus_decoder.py` — `OpusStreamDecoder` wrapping `opuslib.Decoder(fs=16000, channels=1)`. One instance per WS connection, raw RFC 6716 packets in → PCM16 LE mono 16 kHz out.
- `capabilityServices/STTService/src/stt_service/server.py`:
  - `_parse_audio_format(ws) -> (value, source)` mirrors `_parse_language` pattern; reads URL `?audioFormat=pcm16|opus`; defaults pcm16; invalid → fallback + WARN.
  - Per-conn `OpusStreamDecoder` instantiated when format=opus.
  - Binary frame handler: opus packets decoded inline; try/except on decode (per-packet drop + log, don't kill conn).
  - Ready frame echoes `audioFormat`.
- `capabilityServices/STTService/CONTRACT.md` §1.2 — new "Audio format selection — per-connection" section. §2 / §3 / §4.1 / §5.2 amended.
- `gateway/src/adapters/stt/local-stt-adapter.ts`:
  - `appendAudioFormatQuery()` helper mirrors `appendLanguageQuery`.
  - Connect URL composes both query params: `?language=…&audioFormat=…`.
  - **Removed** `acceptEnergy()` (PCM-domain RMS gate) and `downsamplePcm16` from opus path.
  - For PCM path: also removed `acceptEnergy` per Phase 5.5 server-side cleanup.

**Plan said hello-frame negotiation** — we discovered server sends `ready` BEFORE `hello` arrives (CONTRACT §3 invariant). Switched to URL query param mirroring the existing `language` precedent. Plan revised mid-flight; tasks B4–B6 re-spec'd.

### Workstream W — Webui mic opus uplink (opus OUT) — added mid-flight

Phase 5.5 plan deferred webui opus uplink to "Phase 7 if needed". Pulled into Phase 5.5 close per user direction ("tighten up opus in+out for existing stack").

- `gateway/webui/src/audio/opus-encoder.ts` — WebCodecs `AudioEncoder` wrapper. Raw opus packets (not OGG-containerized) at 20 ms frames, 48 kHz mono, 24 kbps. Closed/ready/errored lifecycle with feature-detect (`typeof AudioEncoder === "undefined"` → returns null + `onUnsupported`). Pre-allocated `AudioData` buffer for GC discipline.
- `gateway/webui/src/audio/int16-float32.ts` — inverse of capture-worklet's asymmetric Int16 mapping (`<0 → /0x8000`, `>=0 → /0x7fff`). Round-trip is bit-exact aside from Int16 quantization.
- `gateway/webui/src/hooks/use-voice-client.ts` — capture handler: worklet Int16 → Float32 → RNNoise denoise → speech-prob gate (+ hysteresis hold) → opus encoder → connector.
- `gateway/src/adapters/user-audio-input-adapter.ts` — `sendAudioFrame(bytes: Uint8Array)`; codec-agnostic byte forward; no more `Int16Array` reinterpret.
- `gateway/src/session-handlers/ws-handlers.ts` — binary frame handler forwards Bun `Buffer` directly (extends `Uint8Array`); no more `new Int16Array(...)` reconstruction.
- `gateway/src/bootstrap/stt-factory.ts` — webui sessions ship `audioFormat: "opus"`. Comment marks the cube-sdk per-session override path for Phase 6.

### Workstream N — RNNoise neural noise gate at edge (added mid-flight)

User feedback after webui opus uplink: STT pipeline over-sensitive to room noise (transcribing background "yeah"/"okay"). Industry pattern is neural noise suppression at edge, not server-side VAD threshold tuning.

- `@jitsi/rnnoise-wasm@0.2.1` added to webui deps. ~112 KB raw / ~100 KB gz, lazy-loaded.
- `gateway/webui/src/audio/rnnoise-denoiser.ts` — streaming wrapper. Caller pushes arbitrary-length Float32; wrapper buffers to 480-sample frames; emits `{ samples: Float32, speechProb: number }` per 10 ms frame. Same buffer used for in+out (Jitsi pattern). Lazy WASM via `?url` import.
- `gateway/webui/src/audio/rnnoise-types.d.ts` — ambient module declaration for default export (`createRNNWasmModule`) since Jitsi ships no TS types.
- `gateway/webui/src/hooks/use-voice-client.ts` capture handler — RNNoise speech_prob gate REPLACES echo-gate's `acceptFrame` uplink-drop role. Echo gate still consulted for `snapshot().state` (drives dual-threshold playback hint). Hysteresis hold (1500 ms post-speech) keeps gate open through trailing silence so server-side Silero sees end-of-turn.
- Thresholds tuned to Jitsi production values (lib-jitsi-meet's `VADTalkMutedDetection.ts`):
  - `RNNOISE_BASELINE_SPEECH_PROB = 0.6` (matches `VAD_AVG_THRESHOLD`)
  - `RNNOISE_PLAYBACK_SPEECH_PROB = 0.85` (~ `VAD_VOICE_LEVEL = 0.9`)

### Demolition (incidental)

- `gateway/src/adapters/stt/audio-stream-handler.ts` + test — **deleted**. The PCM silence-carrier was a hack that emitted 2560-byte zero-frames every 80 ms to keep Silero VAD alive between real audio. Corrupted the opus path (server tried to decode zeros as opus packets → OpusError every 80 ms). With continuous client-side opus + RNNoise gate, no longer needed.
- `gateway/src/adapters/stt/energy-gate.ts` + test — **deleted**. Server-side dumb RMS gate replaced by edge RNNoise neural gate.
- `gateway/src/session-handlers/mic-echo-guard.ts` — gutted to start-cooldown only. The tail-ramp logic (held elevated threshold via the echo-gate after TTS drain) is now handled client-side in the RNNoise dual-threshold pattern. `suppressInputFor` survives (initial TTS-burst mute so WebRTC AEC can converge).
- `STTAdapterConfig.energyThreshold` + `ttsPlaybackEnergyThreshold` + `silenceIdleGapMs` — removed.
- `gateway/config.yaml` `stt.energy_threshold`, `tts_playback_energy_threshold`, `silence_idle_gap_ms` keys — removed.
- `shared/config/src/schema.ts` — schema fields dropped.

## What's deferred — Phase 6 cube-sdk

Original Phase 5.5 plan included **Workstream C** (cube HIL smoke + remove `@discordjs/opus` from gateway). C1–C8 were dropped because:

1. Survey found `gateway/src/transports/xiaozhi/` does not exist on `feature/esp32-cube-v2-rescope` — it lives on `feature/esp32-cube-v1`.
2. Re-implementing the xiaozhi-specific WS transport on v2-rescope would replicate 2 000+ lines of code (protocol parser, upgrade handler, cube-session lifecycle, frame translator).
3. User raised the question: *"why can't we make something like a cube-sdk similar to web-sdk, and have the cube reuse the WS from gateway as-it?"* — i.e., unify the cube on the existing client-WS protocol instead of inventing a separate xiaozhi dialect.

Phase 5.5 closes with the gateway prepared for that unified architecture:
- Gateway is codec-agnostic on the STT side (URL-param negotiation already works for both pcm16 + opus).
- Gateway's main client WS endpoint blindly forwards Uint8Array binary frames (W3+W4 — no Int16 reinterpret).
- The `audioFormat: SttAudioFormat` config field on `STTAdapterConfig` is already per-session and can flip to `"opus"` per future cube-sdk client.

**Phase 6 brainstorm topic**: design cube-sdk (C++/ESP-IDF equivalent of web-sdk) that speaks the gateway's existing client WS protocol with opus uplink + opus downlink + cube-friendly auth (TLS pin or shared token, not PASETO). Drops the need for a separate xiaozhi WS endpoint entirely.

**Cube HIL smoke deferred** — `esp32/cube/tests/hil/test_voice_loop.py` + `test_ws_recovery.py` exist on v2-rescope but require the cube-side WS transport, which is Phase 6 work.

## What you need to know

1. **Gateway is a true codec-agnostic byte pipe now.** No PCM-domain operations between WS receive and STT WS send. Anything coming in on the client WS goes out on the STT WS unchanged. Codec is set per STT-adapter-session and travels as a URL query param to the STT server.

2. **Server-side STT pipeline still hardcoded 16 kHz internally** (Silero + Smart-Turn + SenseVoice). Opus path means: client encodes at any opus-valid rate (8/12/16/24/48 kHz); server `opuslib.Decoder(fs=16000)` resamples to 16 kHz output; pipeline gets PCM16. PCM path requires client to send exactly 16 kHz (CONTRACT §2).

3. **RNNoise gate uses Jitsi production thresholds.** Tuned during smoke:
   - `0.5` (Jitsi-stated midpoint) dropped legit speech at 0.47 in real-room smoke.
   - `0.3` was too permissive — false "yeah"/"okay" transcripts.
   - `0.6` is the current per-frame baseline (matches Jitsi `VAD_AVG_THRESHOLD`).
   - If user reports speech being dropped → lower baseline to 0.5 first, then 0.4.
   - If background noise leaks through → raise toward 0.7.

4. **Hysteresis hold (1500 ms post-speech) is load-bearing.** Without it Silero never sees the speech→silence transition because RNNoise drops all post-utterance silence frames. `vad.end` then never fires, Smart-Turn never finalizes, transcript never emits. If you change `RNNOISE_POST_SPEECH_HOLD_MS`, smoke end-of-turn detection.

5. **WebCodecs `AudioEncoder` `format` field nests under `opus`**: `{ codec, sampleRate, numberOfChannels, bitrate, opus: { format: "opus", frameDuration, application } }`. Misplacing `format` at the top level silently produces wrong output (or OGG-framed packets depending on browser). Tested config produces bare RFC 6716 packets, ~60–80 bytes per 20 ms speech frame.

6. **Mic capture sample rate is 48 kHz (browser hardware-native).** W2 attempted 16 kHz to align with STT internal rate but broke browser AEC + AudioContext (silent mic, RMS < 0.005 even on yelling). Reverted in `daab22e`. Opus encoder runs at 48 kHz; server decoder resamples on decode.

7. **WebCodecs OGG-Opus decoder (webui) consumes Fish Audio TTS opus.** That's why the decoder is `ogg-opus-decoder` (with OGG container) while the encoder is raw RFC 6716 (no container). Different formats, different libraries.

8. **Operator action required on host config.yaml.** Operators with `~/.sentient/gateway/config.yaml` containing `energy_threshold`, `tts_playback_energy_threshold`, or `silence_idle_gap_ms` under the `stt:` block must remove those keys — they're rejected by the schema now. The repo's `gateway/config.yaml` template is already updated.

## Open questions / risks

- **iOS Safari < 17.2** lacks WebCodecs `AudioEncoder`. Webui's mic opus path fails gracefully via `onUnsupported` → throws "Voice input requires a recent browser" at startVoiceMode. Text mode still works. iOS 17.2 (Dec 2023) is the floor.
- **Firefox < 130** same caveat (Sept 2024 floor).
- **RNNoise thresholds are device-dependent.** Cheap laptop mics with auto-gain may produce signal levels where 0.6 is wrong. Smoke per-deployment on a real device.
- **No tests for the RNNoise denoiser wrapper** — per testing.md (codec wrappers around browser APIs aren't worth pinning); the wire contract is exercised in browser smoke instead.
- **`shared/web-sdk/src/audio-pre-roll-ring.ts`** (added by develop's a30622f, came in via the develop→v2-rescope merge) is unused by our hook. Left in place as a web-sdk surface for potential Phase 6 cube-sdk reuse. If unused at Phase 6 close, delete.
- **`mic-echo-guard.ts` is now half-empty** (just the start-side TTS cooldown). Could collapse to a single function call at the audio-frame-sender; left as-is to preserve a seam for future hooks.
