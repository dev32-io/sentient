# ESP32 Cube

Waveshare ESP32-S3-Touch-AMOLED-2.16 voice client. Application firmware is owned in [`../firmware/`](../firmware/); board adaptation lives in `firmware/main/boards/sentient-cube/`. Gateway wire contract lives in [`shared/protocol/`](../../../shared/protocol/). Firmware uses current gateway manual-capture protocol: hold touchscreen button to capture, release to submit; assistant playback uses Opus. WSS enforces certificate trust and hostname verification. End-to-end voice behavior remains device-unverified. A successful build is not device smoke.

## Host workflow

1. Source [`scripts/env.sh`](../../../scripts/env.sh) from repository root. It puts external `esp32-devtool` submodule CLI on PATH and points `ESP32_DEVTOOL_BOARDS_DIR` at [`../devtool/boards/cube.yaml`](../devtool/boards/cube.yaml). Initialize submodule if absent (`git submodule update --init esp32/devtool`). Use reviewed submodule revision, not old in-tree devtool instructions.
2. Use reviewed ESP-IDF 5.5.2 sources/dependencies. The manifest minimum `>=5.5.2` is not unrestricted upgrade compatibility; build-local source corrections are hash-pinned. See [build profiles](build-profiles.md) for debug/prod configuration and build-only checks. Current provisioning uses [BLE enrollment](ble-protocol.md), without baked account/Wi-Fi headers. Development TLS accepts an [explicit supplied certificate](../scripts/README.md); release retains CA-bundle verification and excludes that certificate. Never flash an unreviewed compile-only image.
3. For approved connected local device inspection, `esp32-devtool --json info` performs USB discovery and a LAN HTTP request; it is not offline selection inspection. Global flags (`--board`, `--port`, `--boards-dir`, `--json`) go **before** subcommand. Device commands include `esp32-devtool cmd state`, `esp32-devtool daemon ring --port <selected-port>`, `esp32-devtool screenshot --out <private-path>`, and, only with explicit authorization, `esp32-devtool flash --profile debug`. Daemon owns USB serial; do not run competing monitor or serial reader. Debug companion exposes unauthenticated LAN HTTP; enable it only with explicit approval for the development network. **No device flash or runtime smoke is approved by these docs.** Prod flash is not approved.

Source of truth: [cube AGENTS](../AGENTS.md), [repository AGENTS](../../../AGENTS.md), [build details](../../../agents/docs/esp32/cube/build-details.md), [flash discipline](../../../agents/docs/esp32/cube/flash-discipline-details.md), and [devtool README](../../devtool/README.md). HTTP screenshots use devtool companion, not a `ui.snapshot` USB verb. Read [diagnostic restrictions](../../../agents/docs/esp32/cube/agent-console-details.md): tree dumps may expose populated pairing labels even when hidden, and transcript verbs return user content. Never bypass bootstrap screenshot refusal. Historical HIL/private setup notes are not current runbooks.

Firmware target constraints live in [path-scoped cube rules](../../../.claude/rules/esp32/cube-firmware.md); [firmware and asset model](firmware-assets.md) explains USB-only updates, the single application partition and hierarchical read-only resources. Until device migration is verified, these describe the target rather than an already-installed layout.

## Hardware constraints

Preserve AXP2101 PMIC bring-up order and disabled shutdown (shutdown can latch power off); keep safe transient CST9217 touch reads and calibrated `swap_xy=1, mirror_x=0, mirror_y=1`. Keep audio and diagnostic buffers bounded; host-side conversion avoids extra device memory pressure. The host simulator currently compiles only the shared diagnostic test screen at 466x466, not the shipping 480x480 companion UI. It cannot prove physical touch, audio or memory behavior. See [`../AGENTS.md`](../AGENTS.md) before changing hardware paths.
